# NEBians Backend Optimization, Cybersecurity & Android Obfuscation Guide

## 1. Shared cPanel Backend Optimization Architecture

Our production environment runs on a shared cPanel LiteSpeed (`lswsgi`) server with strict per-account limits (`max_user_connections = 10` on MariaDB, `LSAPI_CHILDREN = 6`, shared LVE thread/RAM limits). Every optimization is engineered to minimize SQL connections, Redis socket round-trips, worker memory, and CPU threads:

| Layer | Optimization | File(s) |
| --- | --- | --- |
| **L1 In-Process Worker Cache** | Thread-safe bounded L1 LRU cache (512 keys, 5s TTL in prod, auto-disabled in `manage.py test`) inside `ResilientRedisCache`. Eliminates ~85% of repeat Redis socket round-trips for hot keys (`site_theme`, `library_filter_options`, `home_resources`, `home_stats_v2`, token checks). Immediate in-process eviction on `set`/`delete`/`clear`/`incr`. | `nebians/cache_fallback.py` |
| **LSAPI Parent Pre-Warming** | `passenger_wsgi.py` runs `nebians/warmup.py` once in the parent process before forking workers. Pre-imports `redis`, `pymysql`, `PIL`, `bleach`, `rest_framework.serializers`, `api.serializers`, `api.security`, `api.view_helpers`, `web.view_helpers`, `web.syllabus_data`, populates URLconf, and compiles templates copy-on-write. | `nebians/warmup.py`, `passenger_wsgi.py` |
| **Conditional Daphne Retirement** | Realtime uses hosted Ably (`api/realtime_ably.py`). `restart_workers.sh` now keeps `daphne` retired unless `WS_PUBLIC_URL` or `ENABLE_DAPHNE=1` is set, saving ~127 MB RAM and ~64 LVE threads. | `scratch/restart_workers.sh` |
| **SQL Query & Prefetch Pruning** | `posts_endpoint` joins `poll` via `select_related('user', 'poll')`. `prime_for_serializers` skips re-prefetching `user` and `uploaded_by` when already cached on model instances and only prefetches `poll__options` for rows that actually hold a poll. `user_profile_stats` reuses `is_following` to avoid duplicate `Follow` queries on locked profiles. | `api/view_helpers.py`, `api/views_forum.py`, `api/views_users.py` |
| **Anonymous Feed & Token Micro-Cache** | First-page anonymous `GET /api/posts/` responses are cached for 15s in production, and `get_user_by_auth_token` caches resolved active users for 15s (`auth_user:<hash>`, cleared immediately on logout/revocation) so parallel mobile launch requests do not hit MariaDB 10 times for the same token. | `api/views_forum.py`, `api/security.py` |
| **Analytics Writer Connection Release & Test Isolation** | `nebians/analytics/writer.py` debounces `User.last_active` DB writes to once per 60s per user (`an:touch:<uid>`), closes thread-local MariaDB connections (`connections.close_all()`) immediately after draining each page-view burst so background daemon threads never consume `max_user_connections = 10`, and skips spawning background SQLite writer threads during `manage.py test` to eliminate parallel test lock races. | `nebians/analytics/writer.py` |
| **Analytics & Admin Single-Pass Query Pruning** | `post_reach.record_impressions` uses a 3-query bulk pattern (`SELECT`, `bulk_create(ignore_conflicts=True)`, `UPDATE`) instead of up to 81 per-card queries. `report_library.py`, `report_devices.py`, `views_admin.py` (`admin_dashboard`, `admin_reports`, `admin_posts`, `admin_study_spaces`), and `views_study_lab.py` (`analytics`) replace N+1 and 14-day loop queries with single-pass conditional `.aggregate()` and `.annotate()` queries (eliminating 290+ redundant SQL queries). | `api/post_reach.py`, `nebians/analytics/report_library.py`, `nebians/analytics/report_devices.py`, `web/views_admin.py`, `web/views_study_lab.py` |

## 2. Cybersecurity & Anti-Proxy / Anti-Scanner Hardening

| Threat Vector | Defense Implemented | File(s) |
| --- | --- | --- |
| **OAuth2 & Login Open Redirects** | `_safe_next_url()` enforces `url_has_allowed_host_and_scheme` and strict single-slash relative path validation across `login_page`, `google_login`, `google_oauth_callback`, `github_login`, `github_callback`, and `token_login`. `google_login` rejects arbitrary user-supplied `state` strings. Removed `ftp` from `DeepLinkRedirect.allowed_schemes`. | `web/views_auth.py` |
| **Exploit Scanners & Open-Proxy Probes** | `CrawlerShieldMiddleware` blocks `CONNECT` methods, `HTTP_PROXY_CONNECTION` headers, absolute foreign proxy URLs, and exploit scanner User-Agents (`sqlmap`, `nuclei`, `nikto`, `masscan`, `zgrab`, `gobuster`, `ffuf`, `wpscan`, `acunetix`, etc.) with `403 Forbidden` before sessions, CSRF, or DB run. | `nebians/crawler_shield.py` |
| **Reverse-Proxy Path Override & Framing** | `SecurityHeadersMiddleware` strips `HTTP_X_ORIGINAL_URL` and `HTTP_X_REWRITE_URL`, removes `Server` and `X-Powered-By`, sets `Cross-Origin-Resource-Policy: same-origin` on `/api/` and `/ajax/` (`same-site` elsewhere), `X-DNS-Prefetch-Control: off`, `X-Download-Options: noopen`, and expands `SENSITIVE_PATHS_404`. | `nebians/middleware.py` |
| **AJAX Brute-Force, Info Leaks & Memory Exhaustion** | Added rate limits to `ajax_resource_comment`, `ajax_check_username`, `ajax_set_password`, and `ajax_change_password`. Sanitized 500 error responses in `ajax_user_photos` so raw DB/exception strings never leak. Bounded `_RATE_STORE` in `astroweb_bridge_views.py` to 1,024 keys. | `web/views_ajax.py`, `api/astroweb_bridge_views.py` |

## 3. Irreversible Android Obfuscation & Anti-MITM Network Hardening

1. **System-Only CA Pinning (`network_security_config.xml`)**:
   - `<base-config cleartextTrafficPermitted="false">` trusts only `<certificates src="system" />`. User-installed MITM proxy root certificates (Charles, Burp, Fiddler, Reqable, HTTP Toolkit, mitmproxy) are rejected by the OS across all production connections.
2. **Direct Socket Bypass (`Proxy.NO_PROXY` + `MODERN_TLS`)**:
   - In release builds (`!BuildConfig.DEBUG`), `ApiService`, `NEBiansApp` (Coil image loader), and `RealtimeClient` configure `OkHttpClient` with `.proxy(Proxy.NO_PROXY)` and `ConnectionSpec.MODERN_TLS`, bypassing any Wi-Fi or system HTTP proxy configured on the phone.
3. **Cryptographic Per-Request Proof (`X-Neb-Proof`)**:
   - `DeviceSignalInterceptor` attaches `X-Neb-Proof: t=<epoch>;n=<nonce>;s=<hmac>` signed with an obfuscated key over `method|path|ts|nonce|versionCode`.
4. **Irreversible R8 + Native C++ Symbol Stripping**:
   - `proguard-rules.pro` enables `-renamesourcefileattribute SourceFile`, `-optimizationpasses 5`, `-overloadaggressively`, `-allowaccessmodification`, and strips verbose/debug/info `android.util.Log` calls via `-assumenosideeffects`.
   - `CMakeLists.txt` compiles `libneb_speech.so` with `-fvisibility=hidden -fvisibility-inlines-hidden -ffunction-sections -fdata-sections` and links with `-Wl,--gc-sections -Wl,--exclude-libs,ALL -Wl,-s`.

## 4. Android ANR Elimination, Native OAuth & Main-Thread Discipline

| Area | Architecture & Rule | File(s) |
| --- | --- | --- |
| **Zero WebView / `CookieManager` Init on API Calls** | `WafChallengeInterceptor.browserRequest` and `RealtimeClient.runWebSocket` never call `CookieManager.getInstance()` on normal API calls. Calling `CookieManager.getInstance()` forces Android to initialize the Chromium WebView provider (`WebViewFactory.getProvider()`), which blocks for 1.5s to 5s+ on MIUI/ColorOS/OneUI and caused startup/post-login ANRs. `CookieManager` is touched only after an actual challenge page is solved in `solveChallengeInWebView`. | `WafChallengeInterceptor.kt`, `RealtimeClient.kt` |
| **Signing-Cert-Verified Google OAuth, Bound Partial Custom Tabs Session & Zero-Wait Callback** | `app/build.gradle.kts` extracts registered Android OAuth SHA-1 and SHA-256 hashes (`certificate_hash`) from `google-services.json` into `BuildConfig.GOOGLE_ANDROID_CERT_HASHES`, and `LoginScreen.isNativeGoogleIdConfigured` verifies and caches (`nativeGoogleCertVerified`) the APK's runtime signing certificate off the main thread (`Dispatchers.Default`) before invoking `CredentialManager` (`GetGoogleIdOption`), preventing Play Services from showing a native picker that fails on account selection with `GetCredentialCancellationException("[16] Account reauth failed.")` when the SHA-1 is not registered in Google Cloud Console. `isTrueUserCancellation` also catches `[16] Account reauth failed` / `[28444]` and falls back automatically without popping a second Play Services modal. When using Custom Tabs, `LoginScreen` binds `CustomTabsService`, warms up `CustomTabsSession` with `mayLaunchUrl` directly to `accounts.google.com/o/oauth2/v2/auth` and `github.com/login/oauth/authorize` (eliminating an extra backend redirect round-trip), and launches an 88% height Partial Custom Tab bottom sheet (`setToolbarCornerRadiusDp(24)`). `AuthRepository.authState` (`sessionVersion` + `SharingStarted.Eagerly`), `LoginScreen`, and `Navigation.kt` (`LaunchedEffect(authState, currentRoute)`) transition off `LoginScreen` in `<16ms`. | `LoginScreen.kt`, `app/build.gradle.kts`, `AndroidManifest.xml`, `MainActivity.kt`, `AuthRepository.kt`, `SettingsViewModel.kt`, `Navigation.kt`, `proguard-rules.pro`, `api/views_auth.py`, `web/views_auth.py` |
| **Zero Login Gate, Bounded Splash Warmup & Never-Stuck Skippable Onboarding** | `SplashScreen` bounds auth state warmup with `withTimeoutOrNull(750L)` before `exit.animateTo(1f)` and always enters `Home` directly so guests can browse Library, Notes, Pathways, and Forum immediately (`IntroScreen` / `IntroPages` removed). `InAppUpdateHelper.onResume` is a no-op unless an update was detected, and `MainActivity` once-gates and defers `POST_NOTIFICATIONS` permission prompting so cold starts and OAuth sheet returns are never interrupted. `OnboardingScreen` provides a top-bar Close (`X`) button on step 0, a 1-tap `Skip` action in the top bar on all intermediate steps, Back dismissal (`skipOnboarding` -> `markProfileCompleted()`), pre-seeded `BirthdayStep` ISO date without nested vertical scrollers, and skippable `Birthday`, `Gender`, `Level`, `Subjects`, `Place`, `Campus`, `Portrait`, and `Bio` steps so users are never trapped. | `SplashScreen.kt`, `MainActivity.kt`, `InAppUpdateHelper.kt`, `OnboardingScreen.kt`, `OnboardingStepsIdentity.kt`, `OnboardingFlow.kt`, `CompleteProfileViewModel.kt`, `Navigation.kt` |
| **Zero Main-Thread Disk I/O, Offscreen Layer Recording, JNI `dlopen`, or Heavy Filtering** | Hilt singletons and ViewModels (`AuthRepository`, `SiteThemeRepository`, `SpeechModelManager`, `NotesViewModel`, `SyllabusViewModel`, `PdfAssistantViewModel`, `NoteEditorViewModel`) never run `runBlocking`, synchronous `SharedPreferences.all` scans, main-thread `dlopen("libptts_ffi.so")`, or JSON/Markdown serialization on the main thread. `glassSource` records the offscreen `GraphicsLayer` only when `showBottomBar == true`. `HomeViewModel` and `ForumViewModel` pre-warm `markdownToInlinePreview` on `Dispatchers.Default` before emitting posts. `SecurePrefs` guards Keystore initialization with `initAttempted`, and Coil's `ImageLoader` is decoupled from `WafChallengeInterceptor` WebView initialization. | `NEBiansApp.kt`, `LiquidGlassNav.kt`, `Navigation.kt`, `SecurePrefs.kt`, `WafChallengeInterceptor.kt`, `HomeViewModel.kt`, `ForumViewModel.kt`, `Markdown.kt`, `SpeechModelManager.kt` |
| **CrashHandler Binder & OEM ANR Dialog Guard** | `CrashHandler` truncates stack-trace extras to 32 KB (preventing `TransactionTooLargeException` across `:crash_process`), commits `nebians_crash_logs` synchronously before process termination, and skips `defaultHandler` when `CrashActivity` launches so OEM `ActivityManagerService` does not abort `CrashActivity` with a system ANR/crash dialog. | `CrashHandler.kt`, `CrashActivity.kt` |
