# 2026-09-14 — Blog article page (news_detail) rebuild

## What was wrong
The reported symptom ("I'm signed in but it still says Sign in") plus messy layout.

1. **Auth bug (root cause):** `news_detail.html` used `{% if user.is_authenticated %}`. The
   web views pass `user` through `_ctx()` as a **plain dict**, not a Django `User`, so
   `user.is_authenticated` is a failed dict-key lookup → silently falsy → the page always
   rendered the signed-out branch, and `var IS_AUTH` was always `false` (so comment
   like/bookmark/reply redirected to login). Fixed by using the top-level
   `is_authenticated` context var that `_ctx()` already sets (`bool(token)`), which is
   what `base.html` and `_comment_cards.html` use. Only this template had the bad form.

2. **Comment cards were completely unstyled.** `_comment_cards.html` emits `.fp-reply*`
   markup, but those rules live **only** in `pages/forum-post.css`, which is loaded
   **only** by `forum_post.html`. Any other page including that partial must supply its
   own `.fp-reply*` styling. Added a scoped `.nd-comments .fp-reply*` block.

3. **Layout:** the article and the comments were one giant `overflow:hidden` card, so the
   empty state was welded to the card's rounded bottom; `.news-related` was capped at
   780px while the article was full-bleed (misaligned); `.news-detail-page` used
   `padding: 24px 0 64px`, whose **zero horizontal value overrode `md-container`'s
   gutter** — so on mobile the card touched the screen edges. Fixed with `padding-block`.

4. Also: no back link (`.back-link` CSS existed but was unused), no bottom nav
   (`news.html` defines `{% block bottomnav %}`, the detail page did not), no active
   "Blog" nav state, and no read time.

## Two traps worth remembering
- **`inline-media.js` auto-enhances every `<textarea>` on the page.** It replaces the
  textarea with a `contenteditable` div, sets the original to `display:none`, and
  proxies `.value`. A plain custom textarea silently disappears. Opt-outs are
  `[data-neb-skip]`, `.reply-input-wrapper`, `.fp-compose`. Use `.reply-input-wrapper` +
  `.reply-send-btn` — the site-wide composer pill — for any new comment box.
- **`color-mix()` in the existing CSS is written without `in srgb`**, e.g.
  `color-mix(10%, var(--md-primary), transparent)`, which is invalid and silently
  dropped by the browser. Use `color-mix(in srgb, COLOR N%, transparent)` in new code.

## Verification harness (headless, no browser automation available)
`backend_python/scratch/news_preview/` (gitignored): renders `news_detail.html` against a
real `Announcement` into static HTML, `serve.py` maps `/static/` → `staticfiles/`, and
Chrome `--headless=new --screenshot` captures it. Two gotchas:
- Chrome headless on Windows has a **~500px minimum window width**, so `--window-size=390`
  gives a ~489px viewport and clips the shot. Wrap the page in a **390px-wide `<iframe>`**
  to get a true mobile viewport.
- `--dump-dom` does not include iframe content — have the child write results into
  `parent.document.body` (same-origin) to read them back.
