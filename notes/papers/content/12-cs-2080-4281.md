**Relational data model.** The relational model was proposed by E. F. Codd (1970). It represents the whole database as a collection of **relations (tables)**, each made of rows and columns, and is the basis of MySQL, Oracle, SQL Server and PostgreSQL.

*Terms:*
- **Relation (table):** a two-dimensional set of data with a name.
- **Tuple (row, record):** one entry of the relation. **Attribute (column, field):** a property of the entity.
- **Domain:** the set of allowed values of an attribute. **Degree:** number of attributes; **cardinality:** number of tuples.
- **Primary key:** attribute(s) that uniquely identify each tuple and cannot be NULL. **Foreign key:** an attribute that refers to the primary key of another relation, which links the tables.

*Properties:* each cell holds one atomic value; every column has a unique name; all values of a column are of the same type; rows are unique and the order of rows and columns is not important.

*Example.* Relations STUDENT and CLASS:

| regno (PK) | name | class (FK) | gender |
|---|---|---|---|
| 101 | Sita Rai | 12 | F |
| 102 | Ram Thapa | 12 | M |
| 103 | Hari Karki | 11 | M |

| class (PK) | teacher |
|---|---|
| 11 | Mr. Sharma |
| 12 | Ms. Gurung |

Here STUDENT has degree 4 and cardinality 3, `regno` is the primary key, and `class` is a foreign key that refers to `CLASS.class`, so a student's teacher can be found by joining the tables. Data are manipulated with SQL, for example `SELECT name FROM student WHERE class = 12;`. Integrity rules (entity integrity: a primary key is never NULL; referential integrity: a foreign key value must exist in the parent table) keep the data consistent.

**Or.** (The printed question lists only the schema; the DDL tasks are creation of the table and the usual changes to it.)

```sql
-- 1. Create the table
CREATE TABLE student_info (
    regno   INT PRIMARY KEY,
    name    VARCHAR(25),
    class   INT,
    gender  CHAR(1),
    address VARCHAR(25)
);

-- 2. Add a new column
ALTER TABLE student_info ADD phone VARCHAR(10);

-- 3. Change the size of a column
ALTER TABLE student_info MODIFY address VARCHAR(40);

-- 4. Remove a column
ALTER TABLE student_info DROP COLUMN phone;

-- 5. Remove all rows but keep the structure
TRUNCATE TABLE student_info;

-- 6. Delete the table completely
DROP TABLE student_info;
```
DDL (Data Definition Language) commands CREATE, ALTER, DROP, TRUNCATE and RENAME define or change the *structure* of database objects, and are auto-committed. `regno` is made the primary key so each student is unique.

**Syntax for database connectivity (1 mark).** In PHP (MySQLi, procedural style):
`$conn = mysqli_connect("servername", "username", "password", "databasename");`
(the object style is `$conn = new mysqli($servername, $username, $password, $dbname);`). It returns a connection, or false on failure.

**Insert program (4 marks).** An HTML form collects the data and the PHP script (`insert.php`) saves it.

```html
<form method="post" action="insert.php">
  First name: <input type="text" name="fname"><br>
  Last name:  <input type="text" name="lname"><br>
  Mark:       <input type="number" name="mark"><br>
  Email:      <input type="email" name="email"><br>
  <input type="submit" name="submit" value="Save">
</form>
```

```php
<?php
$servername = "localhost";
$username   = "root";
$password   = "";
$dbname     = "studentDB";

// 1. connect
$conn = mysqli_connect($servername, $username, $password, $dbname);
if (!$conn) {
    die("Connection failed: " . mysqli_connect_error());
}

// 2. read the form values
$fname = $_POST['fname'];
$lname = $_POST['lname'];
$mark  = $_POST['mark'];
$email = $_POST['email'];

// 3. insert the record
$sql = "INSERT INTO student (firstname, lastname, mark, email)
        VALUES ('$fname', '$lname', $mark, '$email')";

if (mysqli_query($conn, $sql)) {
    echo "Record inserted successfully";
} else {
    echo "Error: " . mysqli_error($conn);
}

// 4. close
mysqli_close($conn);
?>
```
**Explanation.** (1) `mysqli_connect()` joins the script to the server and database studentDB; (2) `$_POST` receives the data submitted by the form; (3) the SQL INSERT statement is run with `mysqli_query()`, which returns true on success; (4) `mysqli_close()` closes the connection. In a real application prepared statements (`mysqli_prepare`, `bind_param`) should be used instead of putting the variables in the SQL string, to prevent SQL injection.

**Or. JavaScript factorial.**
```html
<!DOCTYPE html>
<html>
<body>
<script>
  var n = parseInt(prompt("Enter a number:"));
  var fact = 1;
  if (n < 0) {
      document.write("Factorial is not defined for negative numbers");
  } else {
      for (var i = 1; i <= n; i++) {
          fact = fact * i;
      }
      document.write("Factorial of " + n + " is " + fact);
  }
</script>
</body>
</html>
```
**Explanation.** `prompt()` reads the number as text and `parseInt()` converts it to an integer; `fact` starts at 1; the `for` loop multiplies `fact` by 1, 2, ..., n; for n = 5 it gives 1×2×3×4×5 = 120 (and 0! = 1 because the loop does not run). `document.write()` shows the result in the page. The same can be done with a recursive function `function f(n){ return n<=1 ? 1 : n*f(n-1); }`.

@s 12
**Procedural-oriented programming (POP)** divides a program into *functions (procedures)* that work on shared data in a top-down way, e.g. C, Pascal, FORTRAN. **Object-oriented programming (OOP)** builds the program from *objects* that combine data and the functions that work on them, in a bottom-up way, e.g. C++, Java, Python. **Event-driven programming** is a style in which the flow of the program is decided by *events* (a mouse click, key press, timer or message), which are handled by event-handler functions, as in GUI programs, JavaScript, Visual Basic, Android apps.

| Basis | Procedural-oriented programming | Object-oriented / event-driven programming |
|---|---|---|
| Basic unit | Function (procedure) | Object (class) |
| Approach | Top-down | Bottom-up |
| Emphasis | On the procedure (what is to be done) | On the data (objects) |
| Data security | Data are global and open to all functions, so there is little security | Data are hidden inside objects by encapsulation (private, public) |
| Reuse | Functions are copied; low reusability | Inheritance and polymorphism give high reusability |
| Program control | Fixed, step by step order of execution | Controlled by events and user actions (event-driven) |
| Modification | Difficult for large programs | Easy: new objects can be added without changing others |
| Examples | C, Pascal, COBOL | C++, Java, Python, JavaScript |

*Example.* In C a bank program has separate functions `deposit(balance)` and `withdraw(balance)` using shared variables; in OOP an `Account` class holds the balance and its `deposit()` and `withdraw()` methods, and an event such as a click on the "Withdraw" button calls the method.

@s 13
**System testing (1 mark).** System testing is the phase of the SDLC in which the complete, integrated system is run with test data to check whether it meets the requirements and works without errors (after unit testing and integration testing).

**Importance of system testing (4 marks):**
1. *Finds errors before delivery:* bugs, logical mistakes and failures in the interfaces between modules are found and corrected before the users face them, which is far cheaper than fixing them after installation.
2. *Checks the requirements:* it verifies that the system does what the user specified (functional requirements) and meets performance, security and usability needs (non-functional requirements).
3. *Ensures quality and reliability:* the software is tested with normal, boundary and wrong data, and under heavy load (stress testing), so it is stable and gives correct output.
4. *Reduces risk and cost:* it avoids data loss, financial loss and damage to reputation caused by a faulty system, and lowers maintenance cost.
5. *User confidence and acceptance:* a tested system, followed by user acceptance testing (alpha and beta tests), builds the confidence of the client, and the results form the base for the decision to go live.
*Types:* unit, integration, system, acceptance; black-box and white-box testing.

@s 14
**Cloud computing** is the delivery of computing services (servers, storage, databases, software, networking and analytics) over the Internet ("the cloud") on a pay-as-you-use basis, so that users do not need to own and maintain the hardware. Examples: Google Drive, Gmail, Microsoft 365, Amazon Web Services (AWS), Microsoft Azure. *Service models:* SaaS (software), PaaS (platform) and IaaS (infrastructure); *deployment models:* public, private, hybrid.

**Advantages:**
1. *Low cost:* no need to buy expensive hardware and software, and one pays only for what is used.
2. *Scalability and flexibility:* resources can be increased or decreased quickly with demand.
3. *Access from anywhere:* data and applications can be used from any device with an Internet connection, which helps collaboration.
4. *Automatic backup, recovery and updates* done by the provider, so the risk of data loss is lower.
5. *Fast deployment* and no maintenance work for the user.

**Disadvantages:**
1. *Depends on the Internet:* it cannot be used without a good connection, and slow speed affects the work.
2. *Security and privacy risks:* data are stored on the provider's servers, which may be hacked or accessed without permission.
3. *Less control:* the user depends on the provider for downtime, policies and price changes (vendor lock-in).
4. *Long-term cost* may become high for a heavy and continuous use, and there may be legal and compliance problems about where the data are stored.

**Network topology (2 marks).** Network topology is the geometrical arrangement (layout) of the computers, other devices and the links of a computer network, that is, how the nodes are connected to each other. It may be *physical* (the actual cabling) or *logical* (the way data flow). The main types are bus, star, ring, mesh, tree and hybrid.

```figure caption="Four common network topologies: bus, star, ring and mesh."
import numpy as np
fig, axs = plt.subplots(1,4,figsize=(6.4,1.9))
def node(ax,x,y): ax.plot([x],[y],'o',ms=7,color=ACCENT,zorder=3)
ax=axs[0]; ax.plot([0,4],[1,1],color=INK,lw=2)
for x in (0.5,1.5,2.5,3.5): ax.plot([x,x],[1,1.8],color=INK,lw=1); node(ax,x,1.9)
ax.set_title('Bus',fontsize=8)
ax=axs[1]; ax.plot([0],[0],'s',ms=9,color=INK,zorder=3)
for a in np.radians([90,162,234,306,18]):
    ax.plot([0,np.cos(a)],[0,np.sin(a)],color=INK,lw=1); node(ax,np.cos(a),np.sin(a))
ax.set_title('Star (hub/switch)',fontsize=8)
ax=axs[2]; ang=np.radians(np.arange(0,360,60))
ax.plot(np.cos(np.append(ang,ang[0])),np.sin(np.append(ang,ang[0])),color=INK,lw=1.2)
for a in ang: node(ax,np.cos(a),np.sin(a))
ax.set_title('Ring',fontsize=8)
ax=axs[3]; ang=np.radians(np.arange(0,360,72)+90)
for i in range(5):
    for j in range(i+1,5): ax.plot([np.cos(ang[i]),np.cos(ang[j])],[np.sin(ang[i]),np.sin(ang[j])],color=INK,lw=0.8)
for a in ang: node(ax,np.cos(a),np.sin(a))
ax.set_title('Mesh',fontsize=8)
for ax in axs: ax.set_aspect('equal'); ax.axis('off'); ax.set_xlim(-1.4,4.2 if ax is axs[0] else 1.4); ax.set_ylim(-1.3,2.2 if ax is axs[0] else 1.3)
axs[0].set_xlim(-0.3,4.3); axs[0].set_ylim(0.2,2.3)
```

*Brief:* **Bus** – all nodes share a single backbone cable (cheap, easy, but a cable fault stops the network). **Star** – every node is connected to a central hub or switch (easy to manage, one cable failure affects only one node, but the hub is a single point of failure). **Ring** – each node is joined to two neighbours in a closed loop (data pass in one direction by token). **Mesh** – every node is connected to every other (most reliable, but costly: n(n−1)/2 links).

**Guided and unguided media (6 marks).** Transmission media are the paths by which the signal goes from the sender to the receiver.
**Guided (wired, bounded) media** carry the signal along a *physical path* (cable); **unguided (wireless, unbounded) media** carry it through *free space (air, vacuum)* as electromagnetic waves, without any cable.

| Basis | Guided (wired) media | Unguided (wireless) media |
|---|---|---|
| Path of signal | Physical cable or wire | Air or free space, as electromagnetic waves |
| Direction | The signal is directed along the cable | The signal spreads in all directions (broadcast) or in a beam |
| Examples | Twisted pair (UTP/STP), coaxial cable, optical fibre | Radio waves, microwave, infrared, satellite, Bluetooth, Wi-Fi |
| Installation | Cabling is needed, so it is costly and slow to lay in hilly or remote places | Easy and quick; good for hilly, remote and mobile use |
| Security | More secure; tapping needs physical access | Less secure; signals can be intercepted, so encryption is needed |
| Speed / bandwidth | Fibre gives very high speed (Gbps and above); twisted pair 10 Mbps–10 Gbps | Generally lower and shared; affected by distance |
| Interference | Less affected (shielded cables and fibre are immune to EMI) | More affected by weather, obstacles and other signals |
| Mobility | Fixed; devices cannot move freely | Mobile devices can move within the coverage area |
| Cost | Cable and maintenance costs | Lower installation cost, but equipment (antenna, towers, satellites) can be costly |

*Short description of examples.* **Twisted pair** is two insulated copper wires twisted together (telephone, LAN). **Coaxial cable** has a copper core, insulator, braided shield and jacket (cable TV). **Optical fibre** sends light pulses through glass fibre with very high speed and no electrical interference (backbone, Internet). **Radio waves** (3 kHz–1 GHz) travel in all directions (FM radio, mobile phones). **Microwaves** (1–300 GHz) need line of sight between towers (mobile networks, links). **Infrared** is a short-range, line-of-sight signal (TV remote). **Satellite** relays signals through a satellite in orbit (GPS, DTH TV).

**Advantages of pointers (3 marks).**
1. *Dynamic memory allocation:* with `malloc()`, `calloc()` and `free()` memory can be taken and released at run time, which saves memory.
2. *Call by reference:* the address of a variable can be passed to a function, so the function can change the original value and can return more than one result.
3. *Efficient array and string handling:* array elements and strings are accessed quickly by pointer arithmetic.
4. *Dynamic data structures:* linked lists, stacks, queues and trees need pointers.
5. *Direct access to memory and hardware*, and faster execution because the data are not copied; pointers are also used for file handling (`FILE *`).

**C program (5 marks).** The area of the football's circular cross-section is $A = \pi r^2$ (the surface area of a sphere is $4\pi r^2$, see the note).
```c
#include <stdio.h>
#define PI 3.14159

float area(float r)               /* user-defined function */
{
    return PI * r * r;
}

int main()
{
    float radius, a;

    printf("Enter the radius of the football (in cm): ");
    scanf("%f", &radius);

    a = area(radius);             /* function call */

    printf("Area of the football = %.2f sq. cm\n", a);
    return 0;
}
```
**Explanation.** The function `area()` takes the radius as a `float` argument, finds πr² and returns it to `main()`. `main()` reads the radius, calls the function and displays the result. For a radius of 11 cm the output is 380.13 sq. cm. If the *surface area* of the (spherical) ball is wanted, change the return statement to `return 4 * PI * r * r;` (it gives 1520.53 sq. cm for r = 11).

**Or. Structure (2 marks).** A **structure** is a user-defined data type that groups variables of *different data types* under one name, declared with the keyword `struct`; the variables inside are its *members* and are accessed with the dot operator (`s.id`). It is used to store records, such as the details of a staff member.
```c
struct staff {
    int id;
    char name[30];
    float salary;
};
```

**Program (6 marks).**
```c
#include <stdio.h>

struct staff {
    int   id;
    char  name[30];
    float salary;
};

int main()
{
    struct staff s[50];
    int i;

    for (i = 0; i < 50; i++) {
        printf("\nEnter details of staff %d\n", i + 1);
        printf("ID: ");     scanf("%d", &s[i].id);
        printf("Name: ");   scanf(" %[^\n]", s[i].name);
        printf("Salary: "); scanf("%f", &s[i].salary);
    }

    printf("\nStaff with salary from 25000 to 40000\n");
    printf("%-8s %-25s %s\n", "ID", "Name", "Salary");
    for (i = 0; i < 50; i++) {
        if (s[i].salary >= 25000 && s[i].salary <= 40000)
            printf("%-8d %-25s %.2f\n", s[i].id, s[i].name, s[i].salary);
    }
    return 0;
}
```
**Explanation.** `struct staff` has three members; `struct staff s[50]` is an array of 50 structures, one for each staff member. The first loop reads the id, name (`%[^\n]` accepts spaces) and salary of each. The second loop tests the condition `salary >= 25000 && salary <= 40000` and prints only the staff members who satisfy it. The logical operator `&&` makes both conditions necessary.
