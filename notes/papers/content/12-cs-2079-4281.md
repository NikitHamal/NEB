**Differences between centralized and distributed database systems (5 marks).** In a *centralized* database all the data are stored and managed at one site (one computer or data centre), and users reach it through a network. A *distributed* database stores the data in several sites that are connected by a network, and appears to the user as one logical database.

| Basis | Centralized database | Distributed database |
|---|---|---|
| Location of data | All data at a single site | Data spread across many sites (fragmented or replicated) |
| Reliability | Single point of failure: if the site fails the whole system stops | A site failure affects only part of the data; other sites go on working |
| Response / access time | Slow for remote users because every request travels to one site; the central server can become a bottleneck | Fast because data lie close to the users |
| Cost and complexity | Simple and cheaper to set up and maintain | Costly and complex: needs distributed query processing, synchronisation and transaction control |
| Security and control | Easy to secure and control from one place | Harder: many sites to secure and keep consistent |
| Expansion | Hard to scale: the single server must be upgraded | Easy to extend by adding a new site |
| Example | A college's student-record server | A bank with branch databases linked together |

**Or. Purposes of normalization (3 marks) and 2NF example (2 marks).** *Normalization* is the process of organising the tables of a database into smaller, well-structured tables to remove problems. Its purposes are:
1. to **reduce data redundancy** (the same fact stored many times);
2. to **avoid insertion, update and deletion anomalies**;
3. to keep the data **consistent and accurate**, and to save storage;
4. to make each table describe one thing, which makes the database easier to maintain and to extend.

*Second Normal Form (2NF).* A table is in 2NF if it is in 1NF and every non-key attribute depends on the **whole** primary key (no partial dependency).

Example: `Enrolment(StudentID, CourseID, StudentName, Grade)` with the composite key (StudentID, CourseID). `StudentName` depends only on `StudentID` (a partial dependency), so the table is not in 2NF and the name is repeated for every course of the student. Decompose it:

| Table | Attributes |
|---|---|
| Student | **StudentID**, StudentName |
| Enrolment | **StudentID**, **CourseID**, Grade |

Now every non-key attribute depends on the full key of its table, so both tables are in 2NF and the repetition of the name is gone.

**JavaScript program for the factorial of a number (5 marks).** The factorial of $n$ is $n! = n\times(n-1)\times\dots\times1$ with $0! = 1$. The page asks for a number, loops from 1 to $n$ and multiplies.

```html
<!DOCTYPE html>
<html>
<head><title>Factorial</title></head>
<body>
<script>
  var n = parseInt(prompt("Enter a number:"));
  if (isNaN(n) || n < 0) {
    document.write("Please enter a non-negative integer.");
  } else {
    var fact = 1;
    for (var i = 1; i <= n; i++) {
      fact = fact * i;
    }
    document.write("Factorial of " + n + " = " + fact);
  }
</script>
</body>
</html>
```

*Working.* `prompt()` reads the number and `parseInt()` converts it to an integer. The variable `fact` starts at 1; each pass of the `for` loop multiplies it by `i`. For $n = 5$ the loop gives $1\cdot2\cdot3\cdot4\cdot5 = 120$, so the page prints "Factorial of 5 = 120". For $n = 0$ the loop does not run and the result stays 1, which is correct. Negative or non-numeric input is rejected by the `if` test.

**Or. Fetching data from a database in PHP and displaying it in a form (5 marks).** The steps are: (1) connect to the MySQL server, (2) select the database and run a `SELECT` query, (3) fetch the row(s), (4) place the values in the form fields, (5) close the connection.

```php
<?php
$conn = mysqli_connect("localhost", "root", "", "school");
if (!$conn) { die("Connection failed: " . mysqli_connect_error()); }

$id = 1;
$sql = "SELECT id, name, address FROM student WHERE id = $id";
$result = mysqli_query($conn, $sql);
$row = mysqli_fetch_assoc($result);
?>
<form method="post" action="update.php">
  ID:      <input type="text" name="id"      value="<?php echo $row['id']; ?>"><br>
  Name:    <input type="text" name="name"    value="<?php echo $row['name']; ?>"><br>
  Address: <input type="text" name="address" value="<?php echo $row['address']; ?>"><br>
  <input type="submit" value="Update">
</form>
<?php mysqli_close($conn); ?>
```

*Explanation.* `mysqli_connect(host, user, password, database)` opens the connection and returns false if it fails. `mysqli_query()` sends the SQL `SELECT` and returns a result set. `mysqli_fetch_assoc()` returns one row as an associative array (`$row['name']`); a `while` loop is used if many rows are to be listed. The PHP `echo` puts each value into the `value` attribute of an input box, so the form is shown filled with the data from the table. Finally `mysqli_close()` releases the connection. (For input from the user a prepared statement should be used to prevent SQL injection.)

@s 12
**Comparison of object-oriented and procedural programming (5 marks).** *Procedural programming* (C, Pascal, FORTRAN) divides a program into procedures (functions) that act on shared data, and follows the top-down approach. *Object-oriented programming* (C++, Java, Python) builds the program from objects that combine data and the functions that work on them, and follows the bottom-up approach.

| Basis | Procedural programming | Object-oriented programming |
|---|---|---|
| Basic unit | Functions (procedures) | Objects and classes |
| Approach | Top-down: the problem is broken into functions | Bottom-up: objects are designed first, then combined |
| Data and functions | Separate; data are global and passed to functions | Bound together (encapsulation) inside a class |
| Data security | Low: global data can be changed by any function | High: data can be hidden using private members (data hiding) |
| Reusability | Limited: reuse by copying or calling functions | High: through inheritance and classes |
| Features | No inheritance or polymorphism | Encapsulation, inheritance, polymorphism, abstraction |
| Modifying large programs | Hard: a change in the data affects many functions | Easier: changes are confined to a class |
| Real-world modelling | Poor | Close to real-world entities |
| Examples | C, Pascal, BASIC | C++, Java, Python, C# |

In short, procedural programming focuses on *what to do* (the steps), and OOP on *who does it* (the objects), which gives better security, reuse and maintainability for large programs.

@s 13
**Major activities performed to design software (5 marks).** *Software design* converts the requirement specification into a blueprint that the programmers can implement. The major activities are:

1. **Architectural design.** The whole system is divided into major sub-systems or modules and the relations between them are decided (client-server, layered, MVC). This gives the overall structure.
2. **Data (database) design.** The data the system will keep are identified, and entities, attributes and relationships are modelled (E-R diagram, tables, normalization).
3. **Interface design.** How the software communicates with the users, with other systems and with hardware: screens, forms, menus, reports and the user-interface standards.
4. **Component (procedural / detailed) design.** The internal logic of each module is described in detail with algorithms, flowcharts, pseudocode, data-flow diagrams and structure charts or UML class and sequence diagrams.
5. **Design review and documentation.** The design is checked against the requirements for correctness, completeness and feasibility, and a Software Design Document (SDD) is written to guide coding and testing.

A good design is modular (low coupling and high cohesion), traceable to the requirements and easy to maintain. The output of this phase is the design document, which is the input to the coding phase.

**Five application areas of artificial intelligence (5 marks).** *Artificial intelligence* is the ability of a computer or machine to perform tasks that normally need human intelligence: learning, reasoning, perception and decision making. Its popular application areas are:

1. **Expert systems.** Programs that hold the knowledge of a human expert and give advice or diagnoses, for example medical diagnosis (MYCIN) and fault finding in machines.
2. **Natural language processing.** Understanding, translating and generating human language: machine translation (Google Translate), speech recognition, chatbots and voice assistants such as Siri and Alexa.
3. **Robotics.** Robots that sense their surroundings and act, used in car assembly, surgery, space and bomb-disposal work, warehouses and delivery.
4. **Computer vision and pattern recognition.** Machines that interpret images and video: face and fingerprint recognition, number-plate reading, medical imaging, and self-driving cars.
5. **Gaming and decision support / business.** Game-playing programs (chess, Go) that search and learn, recommendation systems (YouTube, Netflix, online shops), fraud detection in banks and stock-market prediction.

Other areas include agriculture (crop monitoring, disease detection) and education (adaptive learning). AI raises concerns such as loss of jobs, privacy and bias, so it should be used responsibly.

**Star topology and ring topology (6 marks).** A *topology* is the physical or logical arrangement of the devices (nodes) of a network.

```figure caption="Star topology (every node joined to a central hub or switch) and ring topology (each node joined to two neighbours in a closed loop)."
fig, (a1, a2) = plt.subplots(1, 2, figsize=(5.6, 2.6))
th = np.linspace(0, 2*np.pi, 6)[:-1] + np.pi/2
for a in (a1, a2):
    a.set_xlim(-1.7, 1.7); a.set_ylim(-1.5, 1.7); a.set_aspect('equal'); a.axis('off')
for t in th:
    a1.plot([0, np.cos(t)*1.2], [0, np.sin(t)*1.2], color=INK, lw=1.2)
    a1.add_patch(plt.Circle((np.cos(t)*1.2, np.sin(t)*1.2), 0.17, fc='white', ec=ACCENT, lw=1.5))
a1.add_patch(plt.Rectangle((-0.22, -0.22), 0.44, 0.44, fc='white', ec=INK, lw=1.6)); a1.text(0, -0.02, 'hub', ha='center', va='center', fontsize=7)
a1.set_title('Star', fontsize=9)
ring = np.linspace(0, 2*np.pi, 200); a2.plot(1.2*np.cos(ring), 1.2*np.sin(ring), color=INK, lw=1.2)
for t in th: a2.add_patch(plt.Circle((np.cos(t)*1.2, np.sin(t)*1.2), 0.17, fc='white', ec=ACCENT, lw=1.5))
a2.set_title('Ring', fontsize=9)
```

*Star topology:* every node is connected by its own cable to a central device (hub or switch); all data pass through that device.
*Ring topology:* each node is connected to exactly two neighbours, forming a closed loop; data travel in one direction (or two in a dual ring) from node to node, usually controlled by a token.

| Basis | Star topology | Ring topology |
|---|---|---|
| Central device | Needs a hub or switch | No central device |
| Failure of one node / cable | Only that node is cut off | The break of one node or cable can stop the whole ring (unless a dual ring is used) |
| Failure of the centre | The whole network fails if the hub fails | Not applicable |
| Adding or removing a node | Easy, without disturbing others | Difficult: the ring must be opened |
| Fault finding | Easy: the faulty link is identified at the hub | Difficult |
| Cabling cost | More cable (one run per node) | Less cable |
| Performance | Good, with no collision when a switch is used | Fair; data pass through every node, and a token prevents collision |

*Advantages of star:* easy to install, extend and troubleshoot; one failed link does not affect the others. *Disadvantages of star:* dependence on the hub, more cable, higher cost.
*Advantages of ring:* orderly access to the medium with no collisions, equal chance for all nodes, short cable. *Disadvantages of ring:* a single failure can halt the network, hard to add nodes and to find faults.

**Cable appropriate for a LAN (2 marks).** The **twisted-pair cable (UTP, e.g. Cat5e or Cat6) with RJ-45 connectors** is the most appropriate cable for a local area network. It is cheap, light and easy to install and terminate, it supports 100 Mbps to 1 Gbps (and above) over up to 100 m, which is enough inside a building, and it works naturally with the star topology and switch. Coaxial cable is bulky and slow for modern LANs, and optical fibre, though very fast and immune to noise, is costly and harder to install, so it is used for the backbone between buildings or floors rather than for each computer.

**Structure (2 marks).** A *structure* is a user-defined data type in C that groups variables of different data types under one name. Each variable inside it is a *member* (field). It is declared with the keyword `struct`, for example

```c
struct student {
    int roll;
    char name[30];
    int age;
};
```
A structure variable is created as `struct student s;` and a member is reached with the dot operator (`s.roll`) or, through a pointer, with `->`. Unlike an array, a structure can hold members of different types, so one record (roll, name, age) is stored as one unit.

**Program (6 marks).**
```c
#include <stdio.h>

struct student {
    int roll;
    char name[30];
    int age;
};

int main() {
    struct student s[5];
    int i;

    printf("Enter the roll, name and age of 5 students\n");
    for (i = 0; i < 5; i++) {
        printf("Student %d\n", i + 1);
        printf("Roll: ");
        scanf("%d", &s[i].roll);
        printf("Name: ");
        scanf("%s", s[i].name);
        printf("Age: ");
        scanf("%d", &s[i].age);
    }

    printf("\n%-8s %-20s %-5s\n", "Roll", "Name", "Age");
    for (i = 0; i < 5; i++) {
        printf("%-8d %-20s %-5d\n", s[i].roll, s[i].name, s[i].age);
    }
    return 0;
}
```
*Explanation.* `struct student s[5]` is an array of five structures. The first loop reads the three members of each student (`scanf("%s", ...)` needs no `&` for a character array). The second loop prints the records in a table with `%-8d` and `%-20s` giving fixed column widths so the output is aligned. Sample output: `101  Ram  17`.

**Or. Program to store and display employee records in a file (8 marks).** A data file `emp.txt` is opened in write mode (`"w"`) with `fopen()`; each record is written with `fprintf()`, the file is closed, reopened in read mode (`"r"`) and every record is read back with `fscanf()` and displayed in a formatted way.

```c
#include <stdio.h>
#include <stdlib.h>

int main() {
    FILE *fp;
    int id, n, i;
    char employee_name[30], post[20];

    fp = fopen("emp.txt", "w");
    if (fp == NULL) {
        printf("File cannot be opened\n");
        exit(1);
    }
    printf("How many employees? ");
    scanf("%d", &n);
    for (i = 0; i < n; i++) {
        printf("Enter ID, employee_name and post: ");
        scanf("%d %s %s", &id, employee_name, post);
        fprintf(fp, "%d %s %s\n", id, employee_name, post);
    }
    fclose(fp);

    fp = fopen("emp.txt", "r");
    if (fp == NULL) {
        printf("File cannot be opened\n");
        exit(1);
    }
    printf("\n%-6s %-20s %-15s\n", "ID", "Employee name", "Post");
    while (fscanf(fp, "%d %s %s", &id, employee_name, post) != EOF) {
        printf("%-6d %-20s %-15s\n", id, employee_name, post);
    }
    fclose(fp);
    return 0;
}
```
*Explanation.* `FILE *fp` is the file pointer. `fopen("emp.txt", "w")` creates the file (and erases an old one), and returns `NULL` if it fails, which is checked. `fprintf()` writes formatted text, one record per line. After `fclose()` the file is opened with `"r"`; `fscanf()` reads one record at a time and returns `EOF` at the end, which stops the `while` loop. The formatted `printf` with field widths shows each record in aligned columns. Names are read with `%s`, so a name must not contain a space (use `_` or `fgets()` for full names).
