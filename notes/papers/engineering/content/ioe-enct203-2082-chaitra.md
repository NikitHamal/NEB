@s 1
**Equivalence relation.** A relation $R$ on a set $A$ is an *equivalence relation* if it is

- reflexive: $(a,a)\in R$ for every $a \in A$,
- symmetric: $(a,b)\in R \Rightarrow (b,a)\in R$,
- transitive: $(a,b)\in R$ and $(b,c)\in R \Rightarrow (a,c)\in R$.

It splits $A$ into disjoint equivalence classes (for example "has the same remainder mod 3" on the integers).

**Partial-equivalence relation (PER).** $R$ is a *partial equivalence relation* if it is **symmetric and transitive** but need *not* be reflexive. A PER is an equivalence relation on the part of $A$ that it relates to something, namely its domain $\{a : (a,a)\in R\}$. Example on $A=\{1,2,3\}$: $R=\{(1,1),(1,2),(2,1),(2,2)\}$ is symmetric and transitive, but $(3,3)\notin R$, so it is a PER and not an equivalence relation.

**Induction.** Let $P(n)$: $13 \mid 4^{2n+1}+3^{n+2}$.

*Basis* ($n=0$): $4^{1}+3^{2}=4+9=13$, a multiple of 13, so $P(0)$ is true.

*Step.* Assume $P(k)$: $4^{2k+1}+3^{k+2}=13m$ for some integer $m$. Then

$$\begin{aligned}
4^{2(k+1)+1}+3^{(k+1)+2} &= 16\cdot 4^{2k+1}+3\cdot 3^{k+2}\\
&= 16\left(4^{2k+1}+3^{k+2}\right)-16\cdot 3^{k+2}+3\cdot 3^{k+2}\\
&= 16\cdot 13m-13\cdot 3^{k+2}\\
&= 13\left(16m-3^{k+2}\right).
\end{aligned}$$

This is a multiple of 13, so $P(k)\Rightarrow P(k+1)$. By the principle of mathematical induction $4^{2n+1}+3^{n+2}$ is a multiple of 13 for every $n\ge 0$. (Check: $n=1$: $64+27=91=13\cdot 7$; $n=2$: $1024+81=1105=13\cdot 85$.)

@s 3
Let $R$: "it is raining", $U$: "Prem has his umbrella", $W$: "Prem gets wet". Premises in clause form (CNF):

| Clause | Source | Form |
|---|---|---|
| C1 | If it is raining, Prem has his umbrella: $R\to U$ | $\lnot R \lor U$ |
| C2 | Prem does not have his umbrella or does not get wet | $\lnot U \lor \lnot W$ |
| C3 | It is raining or Prem does not get wet | $R \lor \lnot W$ |
| C4 | negation of the conclusion $\lnot W$ | $W$ |

Resolution (cancel a literal against its complement):

1. C2, C4 $\Rightarrow$ $\lnot U$ (C5)
2. C1, C5 $\Rightarrow$ $\lnot R$ (C6)
3. C3, C6 $\Rightarrow$ $\lnot W$ (C7)
4. C7, C4 $\Rightarrow$ $\square$ (empty clause)

The empty clause is a contradiction, so the premises together with $W$ are unsatisfiable. Hence the premises entail $\lnot W$: **Prem does not get wet**. $\blacksquare$

**Minimising a DFA (table-filling / partition refinement).**

1. Remove states that are not reachable from the start state.
2. Split the states into two groups: accepting and non-accepting ($0$-equivalence).
3. Refine: two states stay together only if, for every input symbol, they move into the *same group*. Repeat until no group splits ($k$-equivalence $\to$ $(k+1)$-equivalence).
4. Each final group becomes one state of the minimal DFA; the transitions are inherited from any member.

**Example.** DFA for "strings over $\{a,b\}$ ending in $abb$":

| State | on a | on b |
|---|---|---|
| → A | B | A |
| B | B | C |
| C | B | D |
| D | B | E |
| * E | B | A |

- $\Pi_0=\{A,B,C,D\},\{E\}$.
- On $b$: $A\to A$, $B\to C$, $C\to D$, $D\to E$. $D$ goes into group $\{E\}$ while the others stay in $\{A,B,C,D\}$, so $D$ splits: $\Pi_1=\{A,B,C\},\{D\},\{E\}$.
- On $b$: $A\to A$ (group ABC), $B\to C$ (ABC), $C\to D$ (group D), so $C$ splits: $\Pi_2=\{A,B\},\{C\},\{D\},\{E\}$.
- On $b$: $A\to A$, $B \to C$ (different groups), so $A,B$ split: $\Pi_3=\{A\},\{B\},\{C\},\{D\},\{E\}$. No two states are equivalent, so this DFA is already minimal (5 states).

(For a table with a mergeable pair see the minimal-DFA step in the conversion below.)

@s 6
Claim: $L=\{a^p : p \text{ is prime}\}$ is not regular.

Assume $L$ is regular with pumping length $n$. Choose a prime $p \ge n$ (there are infinitely many primes) and $w=a^p \in L$, $|w|=p\ge n$. By the pumping lemma $w=xyz$ with $|xy|\le n$, $|y|=k\ge 1$ and $xy^iz\in L$ for all $i\ge 0$.

Then $|xy^iz| = p + (i-1)k$. Take $i=p+1$:

$$|xy^{p+1}z| = p + pk = p(1+k).$$

Since $k\ge 1$, both factors $p$ and $1+k\ge 2$ are greater than 1, so $p(1+k)$ is a composite number. Hence $xy^{p+1}z = a^{p(1+k)}\notin L$, contradicting the pumping lemma. Therefore $L$ is **not regular**. $\blacksquare$

@s 7
Reading the language: $a^{2n}b^{n}c^{m}$ with $n,m>0$, i.e. twice as many $a$'s as $b$'s, followed by any positive number of $c$'s.

**Grammar.**

$$\boxed{\begin{aligned} S &\to X\,C\\ X &\to aaXb \mid aab\\ C &\to cC \mid c \end{aligned}}$$

$X$ generates $a^{2n}b^n$ ($n\ge 1$) by adding $aa$ on the left and one $b$ on the right in each step; $C$ generates $c^m$ ($m\ge 1$).

**String $aaaabbcc$** ($n=2$, $m=2$).

*Leftmost derivation* (always expand the leftmost variable):

$$S \Rightarrow XC \Rightarrow aaXbC \Rightarrow aa\,aab\,bC \Rightarrow aaaabbC \Rightarrow aaaabbcC \Rightarrow aaaabbcc$$

*Rightmost derivation* (always expand the rightmost variable):

$$S \Rightarrow XC \Rightarrow XcC \Rightarrow Xcc \Rightarrow aaXbcc \Rightarrow aaaabbcc$$

(rules used in the leftmost order: $S\to XC$, $X\to aaXb$, $X\to aab$, $C\to cC$, $C\to c$.)

**Instantaneous description.** The ID (configuration) of a PDA $(Q,\Sigma,\Gamma,\delta,q_0,Z_0,F)$ at any moment is the triple

$$(q,\; w,\; \gamma)$$

where $q$ is the current state, $w$ the *unread* part of the input and $\gamma$ the stack contents (top at the left). The move relation $\vdash$ describes one step: if $\delta(q,a,X)\ni(p,\alpha)$ then $(q,aw,X\beta)\vdash(p,w,\alpha\beta)$. $\vdash^*$ is zero or more steps.

**PDA for $L=\{a^nba^n : n\ge 0\}$** (accept by final state). Push one $a$ for each leading $a$, change state on the middle $b$, then pop one $a$ for each trailing $a$; accept when the input is finished and only $Z_0$ is left.

$M=(\{q_0,q_1,q_2\},\{a,b\},\{a,Z\},\delta,q_0,Z,\{q_2\})$:

| No. | Move | Meaning |
|---|---|---|
| 1 | $\delta(q_0,a,Z)=(q_0,aZ)$ | push the first $a$ |
| 2 | $\delta(q_0,a,a)=(q_0,aa)$ | push every further $a$ |
| 3 | $\delta(q_0,b,Z)=(q_1,Z)$ | middle $b$ when $n=0$ |
| 4 | $\delta(q_0,b,a)=(q_1,a)$ | middle $b$, change to the popping phase |
| 5 | $\delta(q_1,a,a)=(q_1,\varepsilon)$ | pop one $a$ per trailing $a$ |
| 6 | $\delta(q_1,\varepsilon,Z)=(q_2,Z)$ | stack back at $Z$: accept |

@s 9
Let $L_1, L_2$ be context-free languages with grammars $G_1=(V_1,T,P_1,S_1)$ and $G_2=(V_2,T,P_2,S_2)$ with disjoint variable sets.

| Operation | Closed? | Construction / reason |
|---|---|---|
| Union | Yes | new start $S\to S_1\mid S_2$ |
| Concatenation | Yes | new start $S\to S_1S_2$ |
| Kleene star | Yes | $S\to S_1S\mid\varepsilon$ |
| Reversal | Yes | reverse the right side of every production |
| Homomorphism / substitution | Yes | replace each terminal by the start symbol of a CFG for its image |
| Intersection with a regular language | Yes | product of the PDA and the DFA |
| Intersection of two CFLs | **No** | counter-example below |
| Complement | **No** | $L_1\cap L_2=\overline{\overline{L_1}\cup\overline{L_2}}$, and CFLs are closed under union, so complement-closure would give intersection-closure |
| Difference | No | $\overline{L}=\Sigma^*-L$ |

**Example (union).** $L_1=\{a^nb^n\}$: $S_1\to aS_1b\mid\varepsilon$; $L_2=\{c^n\}$: $S_2\to cS_2\mid\varepsilon$. Then $S\to S_1\mid S_2$ generates $L_1\cup L_2$, so the union is context-free.

**Counter-example (intersection).** $L_1=\{a^nb^nc^m\}$ (CFG: $S\to XC$, $X\to aXb\mid\varepsilon$, $C\to cC\mid\varepsilon$) and $L_2=\{a^mb^nc^n\}$ are context-free, but $L_1\cap L_2=\{a^nb^nc^n : n\ge0\}$ is not context-free (pumping lemma for CFL). So CFLs are not closed under intersection, and consequently not under complement.

**Turing machine with storage in the states.** The finite control can remember a *fixed, finite* amount of information, if each state is a tuple $[q,\,x]$ where $q$ is the control state and $x$ is a stored symbol (or several symbols). The states are written $[q_0,a]$, $[q_0,b]$, ... and the machine is an ordinary TM, only the state set is a product $Q\times\Gamma^k$. No extra power is added (the language class is the same), but the design is far simpler.

**How it helps in language recognition.** Whenever a decision depends on a symbol that was read earlier, the symbol is carried in the state instead of being re-found on the tape. Example: $L=\{01^*+10^*\}$ (a first symbol followed by copies of the *other* symbol): the machine stores the first symbol in $[q_1,0]$ or $[q_1,1]$, erases nothing, and then verifies that every later symbol is the opposite one; at the blank it accepts. Similarly the "copy the first symbol to the end", "compare first and last symbol" and the swap in the reversal below need only a few extra states.

A **Universal Turing Machine** $U$ takes the description $\langle M\rangle$ of any TM $M$ together with an input $w$ and simulates $M$ on $w$. For that, $M$ must be written as a string over a fixed alphabet (here $\{0,1\}$), which is the *encoding*.

1. Number the states $q_1,q_2,\dots,q_n$ ($q_1$ start, $q_2$ accepting), the tape symbols $X_1,X_2,\dots$ ($X_1=0$, $X_2=1$, $X_3=$ blank) and the directions $D_1=L$, $D_2=R$.
2. Encode each move $\delta(q_i,X_j)=(q_k,X_l,D_m)$ as
$$0^i\,1\,0^j\,1\,0^k\,1\,0^l\,1\,0^m$$
(1 acts as a separator, and the block never contains two consecutive 1s).
3. The whole machine is the list of its encoded moves separated by $11$:
$$\langle M\rangle = C_1\,11\,C_2\,11\cdots C_r\,111\ \text{(then the input)}$$
4. $U$ is a multi-tape machine: tape 1 holds $\langle M\rangle$ (read only), tape 2 holds the simulated tape of $M$, tape 3 holds the current state of $M$ (as $0^i$). Each step $U$ searches tape 1 for the block that begins with the current state and the scanned symbol, then rewrites the symbol, moves and changes the state. If no block matches, $M$ halts and so does $U$.

**Example.** The bit-complement machine $(q_0 \to q_1,\ q_f \to q_2,\ 0=X_1,\ 1=X_2,\ B=X_3)$ has the three moves

| Move | $i,j,k,l,m$ | Code |
|---|---|---|
| $\delta(q_1,X_1)=(q_1,X_2,R)$ | 1,1,1,2,2 | `01010100100` |
| $\delta(q_1,X_2)=(q_1,X_1,R)$ | 1,2,1,1,2 | `01001010100` |
| $\delta(q_1,X_3)=(q_2,X_3,S)$ | 1,3,2,3,2 | `010001001000100` |

so its code is the three blocks joined by $11$:

`01010100100110100101010011010001001000100`

(the whole string is 41 symbols long). $U$ reads this string from tape 1, together with the input from tape 2.

@s 14
**Halting problem.** Given a Turing machine $M$ and an input $w$, decide whether $M$ halts (accepts or rejects, but does not loop forever) on $w$. $\textit{HALT}=\{\langle M,w\rangle : M\text{ halts on }w\}$ is **undecidable** (it is recursively enumerable but not recursive).

*Proof sketch.* Suppose a decider $H(\langle M,w\rangle)$ exists. Build $D(\langle M\rangle)$: run $H(\langle M,\langle M\rangle\rangle)$; if $H$ says "halts" loop forever, otherwise halt. Run $D$ on its own code: $D$ halts on $\langle D\rangle$ iff $H$ says it does not halt, a contradiction. So $H$ cannot exist.

**Closure properties of recursively enumerable (RE) languages.**

| Operation | Closed? | Reason |
|---|---|---|
| Union | Yes | run both TMs alternately (dovetail); accept if either accepts |
| Intersection | Yes | run both; accept if both accept |
| Concatenation | Yes | non-deterministically split $w=uv$, run $M_1$ on $u$ and $M_2$ on $v$ |
| Kleene star | Yes | non-deterministic split into pieces, test each |
| Reversal | Yes | reverse the input first, then run $M$ |
| Homomorphism | Yes | guess a pre-image |
| Complement | **No** | if $L$ and $\overline L$ were both RE then $L$ would be recursive; $\textit{HALT}$ is RE but its complement is not |

@s 15
The **lexical analyzer (scanner)** is the first phase of a compiler. It reads the source program as a stream of characters, groups the characters into the smallest meaningful units called **lexemes** and outputs a **token** $\langle \text{token-name},\text{attribute}\rangle$ for each lexeme.

1. *Read and clean:* characters are read through an input buffer; white-space and comments are discarded, line numbers are counted for error messages.
2. *Match patterns:* each token class (identifier, keyword, number, operator, punctuation) is described by a regular expression, for example identifier $=\text{letter}(\text{letter}+\text{digit})^*$, integer $=\text{digit}^+$. The expressions are compiled into one DFA; the scanner runs the DFA and uses the longest match.
3. *Emit tokens:* when the DFA reaches an accepting state the lexeme is looked up in the symbol table (keywords are recognised, new identifiers are entered) and the token is passed to the parser.
4. *Errors:* a character that fits no pattern is reported as a lexical error.

Example: `int count = 10;` gives the tokens `<keyword,int>`, `<id,count>`, `<op,=>`, `<number,10>`, `<punct,;>`.

@s 16
The **syntax analyzer (parser)** receives the stream of tokens from the lexical analyzer and checks whether it can be generated by the **context-free grammar** of the language. If it can, the parser builds a **parse (syntax) tree**; if not, it reports a syntax error, which shows that the block of code is not syntactically correct.

Example grammar for assignment and arithmetic expressions:

$$\begin{aligned} \textit{stmt} &\to \textit{id} = \textit{expr}\ ;\\ \textit{expr} &\to \textit{expr} + \textit{term} \mid \textit{term}\\ \textit{term} &\to \textit{term} * \textit{factor} \mid \textit{factor}\\ \textit{factor} &\to (\textit{expr}) \mid \textit{id} \mid \textit{num} \end{aligned}$$

*Valid code* `x = a + 2 * b;` has the token string `id = id + num * id ;`. The parser can derive it, and the tree below (multiplication binds tighter than addition) is produced.

*Invalid code* `x = a + * b;` gives `id = id + * id ;`. After `+` the grammar expects a term (`id`, `num` or `(`), but the parser finds `*`, so no derivation exists and the parser reports "syntax error: expected operand before '*'" (and may recover by skipping to the `;`). Likewise an unmatched `(` or a missing `;` is detected because the token string is not in the language of the grammar. Syntax analysis therefore checks the *structure* of the program (bracket matching, statement form, operator-operand order), while meaning (types, declarations) is checked later by semantic analysis.
